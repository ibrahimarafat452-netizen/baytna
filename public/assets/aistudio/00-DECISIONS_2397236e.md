# 00-DECISIONS — قرارات لاحقة تسبق PRD وPLAN (وتسبق ما يخالفها في CONSTITUTION بقرار صاحب المشروع)
تاريخ: 2026-11-26

## الستاك (يستبدل §١ في PLAN)
- الواجهة: React + Vite + TypeScript strict + Tailwind (RTL) + vite-plugin-pwa. لا Next.js.
- الخلفية: Supabase فقط (Postgres, Auth, Realtime, RLS, Edge Functions, pg_cron). ممنوع Firebase/Firestore.
- الاستضافة: Cloudflare Pages. الوسائط: Supabase Storage خلف طبقة تجريد (Storage interface) لإمكان النقل إلى R2.
- المراقبة: Sentry بإعدادات خصوصية صارمة. لا PostHog ولا أي SDK تحليلات طرف ثالث.
- الكود فقط في الواجهة. أي SQL أو سياسة RLS أو Migration يكتبه صاحب المشروع (بمراجعة خارجية) في supabase/migrations. لا تعدّله ولا تولّده.

## قواعد قاعدة البيانات
- كل جدول جديد: RLS مفعّلة تلقائيًا، وبلا GRANT تلقائي للـ API؛ الصلاحيات صريحة داخل الـ migration.

## دخول الطفل (يستبدل أي وصف مخالف في PRD F1)
- الطفل بلا إيميل ولا موبايل ولا بيانات شخصية.
- الأب ينشئ حساب الطفل ويولّد كود رقمي من ٦ أرقام صالح لفترة قصيرة، ويُدخله على جهاز الطفل. QR اختياري إضافي لنفس الكود.
- الكود يُتحقق منه في الخادم مع حد للمحاولات.

## المحتوى والمسابقات
- لا ترتيب ولا تفوّق بين الأطفال: الشارات تشجيعية («بطل المساعدة») وقد تُمنح لأكثر من طفل. لعبة «مين يعرف مين» بلا نتيجة مقارنة.

## أسلوب العمل
- منصة إنتاج وليست MVP. مهمة صغيرة واحدة في المرة، ثم شرح ما تغيّر وما يُختبر.
- ترتيب المهام: الأساس (حسابات/هيكل/مخطط+RLS/دخول/PWA) ← الوسائط ← الحائط ← التحديات ← الإشعارات ← رسائل الأب ← لوحة الأب ← السلسلة ← اللقاءات ← الألعاب ← المسابقات ← الاشتراك ← التصدير/الحذف ← التصلّب والاختبارات.
