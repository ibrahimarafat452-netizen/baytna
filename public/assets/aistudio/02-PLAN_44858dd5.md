# خطة التنفيذ — «بيتنا»
> مبنية على PRD 1.0. المدة المقدّرة: **١٢ أسبوعًا** لمطوّر واحد باستخدام أدوات الذكاء الاصطناعي. التقديرات تقريبية وتُراجع بعد الأسبوع الثاني.

---

## ١. المعمارية المقترحة

| الطبقة | الاختيار المقترح | السبب |
|---|---|---|
| الواجهة | **Next.js (App Router) + TypeScript + Tailwind (RTL)** | PWA ناضج، SSR، مجتمع كبير |
| PWA | Service Worker (Serwist/Workbox) + Web App Manifest | Offline وPush |
| الخلفية | **Supabase** (Postgres + Auth + Realtime + RLS + Edge Functions) | أسرع طريق لبيت معزول وبيانات لحظية |
| تخزين الوسائط | **Cloudflare R2** (روابط موقّعة) أو Supabase Storage | تكلفة خروج منخفضة للفيديو |
| الإشعارات | Web Push (VAPID) عبر Edge Function/Worker | بلا طرف ثالث |
| الجدولة | `pg_cron` أو Supabase Scheduled Functions | رسائل الأب، الملخص الأسبوعي |
| الفيديو المباشر | رابط Google Meet/Jitsi في v1 | أسرع، ويُدمج لاحقًا |
| الدفع | Paymob أو ما يعادله (التحقق من المحافظ والفوري) | سوق مصري |
| المراقبة | Sentry + PostHog (استضافة ذاتية أو ضبط خصوصية صارم) | بدون تتبع مزعج |

> **ملاحظة:** تُحسم هذه الخيارات في المرحلة صفر بعد تجربة صغيرة (spike). يمكن استبدال أي طبقة بما يناسب خبرتك وأدواتك الحالية.

### نموذج البيانات (مبدئي)
```
households(id, name, avatar, tz, quiet_hours, plan, trial_ends_at, storage_used)

scheduled_messages(id, household_id, from_member, to_members[], media_key, send_at, recurrence)
meetings(id, household_id, starts_at, link, status)

contests(id, household_id, template_id?, title, type, start, end, reward)
```

## ٢. المراحل

### المرحلة ٠ — التمهيد والتحقق (الأسبوع ١)
- مقابلة ٨–١٠ آباء/أمهات (ابدأ بأولياء أمور مركز I Can).
- أسئلة: كام مرة بتكلم ولادك؟ بتعمل إيه؟ هتدفع كام؟ إيه اللي بيخوّفك؟
- Spike تقني: تسجيل فيديو → ضغط → رفع → Push على Android وiPhone.
- حساب تكلفة التخزين لكل بيت.
- نموذج أولي (Figma/HTML) لشاشتين: الحائط ولوحة الأب.
- **المخرج:** قرارات المعمارية والسعر المبدئي، وتأكيد الفكرة.

### المرحلة ١ — الأساس (الأسابيع ٢–٣)
- إعداد المشروع، CI، البيئات (dev/staging/prod).
- الحسابات، البيوت، الأدوار، الدعوات (F1).
- RLS واختباراتها (الأهم أمنيًا).
- نظام التصميم: ألوان دافئة، خط عربي، أفاتارات، مكوّنات كبيرة، دعم RTL.
- PWA shell: manifest، أيقونات، offline أساسي.
- **المخرج:** بيت واحد بأربعة أفراد يدخلون ويشاهدون حائطًا فارغًا بأمان.

### المرحلة ٢ — النواة (الأسابيع ٤–٥)
- التقاط ورفع صورة/صوت/فيديو مع ضغط ورفع بالخلفية (F3).
- حائط البيت والتفاعلات والردود الصوتية (F2).
- محرّك «تحدي اليوم» (اختيار من المكتبة حسب البيت).
- Web Push وتذكيرات الوقت وساعات الهدوء (F11).
- **المخرج:** حلقة «تحدٍّ → رفع → تفاعل» تعمل يوميًا بين جهازين.

### المرحلة ٣ — الأب والرسائل (الأسابيع ٦–٧)
- رسائل الأب المجدولة وردّ سريع ونبضة «وحشتني» (F4).
- لوحة الأب ومهمة اليوم وإدخال الوقت المتاح (F5).
- ملخص الأسبوع (حساب + قالب + إشعار) (F5).
- سلسلة أيام البيت (F9).
- **المخرج:** أب تجريبي يستخدم البرنامج أسبوعًا بدقيقة يوميًا.

### المرحلة ٤ — اللقاءات والكروت (الأسابيع ٨–٩)
- جدولة اللقاءات وفرق التوقيت وتذكيرها (F6).
- كروت متزامنة Realtime: قلب الكارت، المؤقّت، تغيير الدور (F6).
- الألعاب الثمانية (F7) بواجهات خفيفة.
- المسابقات والنقاط الجماعية والشارات (F8).
- محرّر الأهل (F10).
- **المخرج:** لقاء كامل ٢٠ دقيقة بنجاح على بيت حقيقي.

### المرحلة ٥ — الاشتراك والصقل (الأسبوعان ١٠–١١)
- رحلة الأسبوع التجريبي وقاعدة التمديد (F12).
- الدفع والاشتراكات والـ webhooks ومهلة السماح.
- تصدير البيانات وحذفها.
- أداء: ضغط، تقليل حجم الـ bundle، اختبار 3G.
- اختبار أمني للعزل، سياسة الخصوصية، مراجعة قانونية.
- **المخرج:** نسخة Beta مكتملة.

### المرحلة ٦ — تجربة ميدانية وإطلاق (الأسبوع ١٢ وما بعده)
- ١٠ بيوت حقيقية لمدة ٤ أسابيع.
- أسبوعيًا: مراجعة المقاييس، مكالمات قصيرة مع الآباء، إصلاحات سريعة.
- قرار الإطلاق وفق معايير PRD §16.
- **بعدها:** الإصدار الثاني بترتيب الأولوية (كتاب البيت ثم كبسولة الزمن ثم مكتبة الصوت).

## ٣. خط المحتوى (يسير بالتوازي)
| الأسبوع | العمل |
|---|---|
| ١–٢ | هيكل الوسوم، ٣٠ كارت تجريبي |
| ٣–٥ | ١٥٠ عنصر (كروت، تحديات) |
| ٦–٨ | إكمال ≈ ٢٦٥ عنصر |
| ٩–١١ | اختبار مع أطفال حقيقيين وتعديل |
| ١٢+ | دورة محتوى أسبوعية جديدة |

## ٤. الاختبار
- **وحدات/تكامل** للمنطق: السلسلة، النقاط، الجداول الزمنية.
- **اختبارات RLS آلية:** مستخدم من بيت (أ) لا يقرأ ولا يكتب في بيت (ب).
- **E2E (Playwright)** للرحلات: إنشاء بيت، تحدٍّ، لقاء، مسابقة، اشتراك.
- **أجهزة حقيقية:** Android منخفض المواصفات، iPhone، تابلت.
- **اختبار قابلية الاستخدام:** جدّة بزر واحد، طفل ٦ سنوات، أب متعب.

## ٦. مخاطر التنفيذ
| الخطر | الإجراء |
|---|---|
| تعقيد iOS PWA | spike مبكر، شرح تثبيت داخل التطبيق |
| ضغط الفيديو على أجهزة ضعيفة | جودة تكيفية + مدة قصيرة |
| تمدد النطاق | أي فكرة جديدة تدخل «الإصدار ٢» إلا بقرار صريح |
| الإرهاق من تعدد الميزات | تسليم أسبوعي قابل للتجربة |
| الدفع يتأخر | دفع يدوي (تحويل/محفظة) مؤقتًا للبيوت الأولى |

## ٧. أول ٧ مهام عند بدء التنفيذ
1. إنشاء المستودع وهيكل المشروع حسب ملف Constitution.
2. إعداد Supabase ومخطط البيانات وRLS.
3. نظام التصميم RTL وشاشة الدخول.
4. إنشاء البيت والدعوات.
5. التقاط ورفع صورة (أبسط مسار).
6. حائط البيت.
7. إشعار Push تجريبي على جهازين.
